## 1. 当前实现核对（1.0.8）

| 项目 | 代码中的实际行为 | 当前边界 |
| --- | --- | --- |
| 近手触碰 | 手部采样点距昆虫根位置小于 9 cm，触发反馈动画及轻声；单只冷却约 2 s | 是距离阈值，不是手指与虫体表面的精确接触；张掌时采样掌心，否则食指尖，右手优先 |
| 伸手邀请 | 食指伸出或张掌，移动速度低于 0.25 m/s 并稳定约 0.7 s | 蝴蝶可受邀；瓢虫需先在手附近 35 cm 内；独角仙、毛毛虫未接入邀请 |
| 选择哪只 | 优先上次放入的目标，否则取列表中最后一个符合资格的作品 | **没有按凝视选目标**，所以可能不是正在看的那只 |
| 手上停留 | 接近并停在手部点附近；一次邀请从接近开始最多约 7 s | 不是落手后再停 7 s；快速移手、手势解除或追踪失效取消；不是逐足贴合掌面/指面 |
| 「请它靠近」按钮 | 让候选蝴蝶向固定的近前方位置靠近，约 5 s | 只有蝴蝶执行此按钮的靠近路径，不能替代各物种手部互动 |
| 日常活动 | 按已采样路线停留、爬行、转向或小范围飞行 | 转向是路径朝向变化，有些状态复用同一动画 |
| 凝视反馈 | Stage 尚未为昆虫接入独立 Hover 命中与高亮 | Shared Space 的按钮高亮不等于 Stage 昆虫高亮 |
| Shared Space 预览 | 捏合拖动转向；直接 poke 或短捏合点击触发触碰动作 | 与 Stage 当前的手部距离逻辑不同 |

## 2. 当前每种昆虫的五段动画

这是正在接入的 **20 段 GLB 动画**，不是早期规划文档中的完整愿望清单；已接入不代表所有动作的真机观感已验收。

| 昆虫 | 当前五段动画 | 如何触发/复用 |
| --- | --- | --- |
| 蝴蝶 | 停栖轻动 `butterfly_idle_perch`；扇翅飞行 `butterfly_fly`；起飞惊动 `butterfly_startle`；触碰回应 `butterfly_perch_touch`；整理触角 `butterfly_antenna_groom` | 日常停飞切换或手部邀请；近手触碰；整理触角主要用于手上停栖。没有独立走路、转身、落地片段 |
| 独角仙 | 静止 `idle`；步行 `walk`；触碰 `touch`；开甲起飞 `takeoff`；飞行 `flight` | 日常路线自动走动/短飞，触碰近手触发；转向复用 walk，降落倒放 takeoff；未接入飞到手上 |
| 瓢虫 | 静止 `idle`；步行 `walk`；触碰 `touch`；开甲起飞 `takeoff`；飞行 `flight` | 与独角仙同类状态，但使用自身骨架动作；近手符合条件可受邀，转向/降落同样复用 |
| 毛毛虫 | 呼吸 `caterpillar_idle_breathe`；蠕动 `caterpillar_crawl`；抬头探索 `caterpillar_explore`；好奇回应 `caterpillar_touch_curiosity`；缩身 `caterpillar_recoil` | 路线爬行；闲置约 3.4–5 s 后探索；慢速触碰好奇回应，较快触碰缩身；不飞、不自动爬到手上 |

触碰片段目前统一压到约 1.1 s，毛虫缩身约 1.4 s。蝴蝶整理触角主要依赖手上停留，甲虫的转向/落地又复用片段，都是动作区分度需要检查的地方。后续以近处可辨的准备动作、主反应、恢复动作分段调节节奏，而不是只提高播放速度或振幅。

## 3. 场景与天空方案

建议采用 **明亮蓝紫星夜 + 小范围环绕荷塘**。不改成白天，也不以强烈霓虹或全屏泛光抬亮。

- 星空有可辨的浅蓝紫地平线、细星点与少量云层；四周均有背景，不留纯黑扇区。画面保留足够开口看天。
- 近处叶片保持绿色、木头保持棕色、昆虫保留原画颜色；叶背可辨，接触处有柔和阴影；花与萤火只作局部点缀。
- 水面承接较宽的天空亮度变化，保持蓝青色、弱波纹；不使用紫色条纹、密集白色闪点或镜面金属观感。
- 当前 `SceneLighting.kt` 已有天空球、天空 IBL、主光与补光，并非代码里完全没有光。黑底的根因尚未定位；需要分开验证天空可见性/剔除/遮挡/色彩、材质与曝光，不能只调大灯光值。
- 更换天空后同步重建相匹配的环境光和静态水面反射。现有静态探针不提供动态昆虫倒影，不在概念图评审中把它承诺为已实现效果。

## 4. 以用户为中心的 360° 布局

不整体缩放场景，也不缩小昆虫；保留单体尺寸，通过移位、删减和重新编排缩小实体范围。

- 入场时建立以用户站立/坐姿所在位置为中心、以入场朝向为正前方的布局基准。SDK 文档描述 Stage 原点在脚底；眼睛不是 `(0,0,0)`，近手表面高度应按实际入场姿态校准。
- 当前花园仍使用 `(0, 0.36, -4.75)` 的整体偏移，源于旧 Blender 正面相机匹配；新方案不继续以单个前向相机画面决定所有摆放。
- 用户中心约 0.45–0.6 m 保持空净，避免叶片、树干挡脸；最近可交互的叶缘/木面距用户约 0.45–0.85 m。以上是设计初值，需真机校准。
- 中景实体主要落在约 1–3 m 范围；更远处用天空/背景轮廓表现，不铺满不可触及的高面数荷叶和水草。图中远景只代表背景意向。

| 方向 | 布置重点 |
| --- | --- |
| 前方 | 主要观虫荷叶、少量荷花、开阔水面和星空 |
| 左侧 | 矮倒木与毛虫/独角仙观察点；前左方放返回魔法球 |
| 右侧 | 瓢虫叶片、蝴蝶落点，保留伸手空间 |
| 后方 | 低矮叶片、少量花与萤火；有自然内容但不复制一面密集植物墙 |

首轮摆放预算：全环 8–12 片主要荷叶、3–5 朵荷花、4–6 组稀疏草丛、2–3 个木质主体。按原有单体尺寸检查是否过密后再调整。减少远景不等于性能已达标，仍需在目标刷新率下验证 0/1/10 只昆虫的帧时间、加载与转头表现。

## 5. 穿模与表面关系

红框 1 可见木头/苔藓与前景叶片交叠。仅凭截图尚不能区分所有问题来自几何相交还是 MASK 材质/深度排序。

批准布局后，逐个检查倒木、苔藓卡片、荷叶的真实空间关系，分离不应相交的表面；树干基部接入水面，叶柄与叶片正确连接。重新摆放必须同步重采样昆虫路线、起落净空和出生点。验收覆盖四个方向、坐姿/站姿及叶片上下方，不能只以单张 Blender 正面渲染通过。

## 6. 用场景物件代替常驻面板

- **返回魔法球**：前左下方，直径约 8–10 cm，柔和珍珠紫光，内含简单画笔符号；平时无文字，凝视时才显示「回到画板」。轻触或凝视后捏合返回 Shared Space，返回期间忽略重复点击。
- 球随场景固定，不贴脸追随视线、不闪烁抢注意力；回头仍可找到它。保留系统返回及加载失败时的明确退出路径。
- 音乐/自然声音量放在 Shared Space 设置，Stage 沿用；移除常驻按钮列、计数和手势说明。首次指引短暂出现后淡出。
- 取消「请它靠近」按钮。建议采用 **看向昆虫 → 原生目标高亮 → 捏合一次明确选择 → 伸出食指/摊掌并停稳 → 昆虫靠近**。确认目标后再邀请，避免只伸手就把另一只虫吸引过来。
- 蝴蝶落食指/掌心；瓢虫优先掌心或邻近叶缘；独角仙优先宽叶面，之后再验证掌心停靠；毛虫只作近处触碰回应，未有连续表面路径时不飞、不瞬移到手上。
- 邀请一次只处理一只；接近、准备落下、落稳、停留、离开应清晰可辨。建议停留时间从落稳后开始计算，约 2–4 s，再按体验调整。

## 7. 凝视高亮设计

目标为只给当前命中的一只昆虫加柔和浅青白轮廓，保留涂色、纹理与立体明暗；移开视线淡出，不同时点亮整群、不透过树干或荷叶显示。

技术先验证本地 6.1.0 的 `HoverEffectComponent + CollisionComponent + InteractableComponent`，特别是蒙皮动画、多子网格和四种轮廓。公开文档只保证基础交互视觉反馈，本地组件没有公开描边宽度/颜色配置；概念图中的指定轮廓样式尚未得到 SDK 真机验证。若原生效果不足，应先交付一个真实模型高亮小样再确定替代方式，不能把整虫改色当作轮廓验收。

纯凝视的视觉反馈交由系统；显式捏合事件再确认目标，不假设应用能读取系统内部 Hover 状态，也不用头部朝向冒充眼动。

## 8. 后续实施与验收顺序

1. 用户确认概念图的明亮度/星空风格、环绕布局、魔法球与交互方式。
2. 真机小样验证天空可见、近处材质明暗、单只昆虫目标高亮及返回入口；先解决渲染链路差距。
3. 依据确认布局调整真实资产，重建路线和反射；导出 GLB 再导入对照，不用概念图充当最终模型证据。
4. 真机逐个触发四种昆虫动画，检查起落/触碰/取消；再验证全环场景、10 只昆虫负载及进出 Stage。
