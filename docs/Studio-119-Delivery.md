# 1.0.19 · 冷启动画板可见性

## 问题与改动

1.0.18 冷启动时顶部栏与画具可见，中央画板的附属原生窗口却处于 GONE / NO_SURFACE。实体挂载、enabled 和 Activity RESUMED 都正常，不能证明该面板已显示。

- 普通画板由主窗口直接承载，不再在首次恢复时自动替换为 SpatialView 附属面板。
- 仅显式打开 3D 预览时创建附属面板；暂停时释放，恢复时按当前前台状态创建。
- 在实际 Android 内容 attached、shown、windowVisibility=VISIBLE 且有尺寸之前保留普通画板。持续前台 6 秒仍不可用就退出预览，画作不丢失。
- 预览成功后保留原先画板与模型共用的空间命中树，按钮仍需单独验证。
- 回归脚本支持中英文、原地失败采样，以及预览和 Stage 返回检查。
- Stage 关闭前恢复主画板与原先打开的作品册；不再在 Stage 关闭后调用 Stage 专用恢复 API，也不再定时销毁/重建作品册。

## 验证

- Gradle 构建成功；126 项单元测试通过；Lint 0 错误、35 警告。
- 修改前：Awake 状态下原地语义检查失败，缺失中央画纸及按钮。
- 用户已确认最终候选“中心面板可见，preview 3D 模型可见”。
- 画板候选连续 3 次冷启动，各次作品册开关后仍有画纸/按钮；预览中打开新画纸确认框并取消通过；切换物种后恢复普通编辑界面通过。此后仅修改 Stage 返回流程，未改画板和预览代码。
- 最终 APK 在设备 Awake 下完成两次 Stage 全加载后返回，覆盖作品册原先关闭/打开；主画板和作品册状态均恢复，测试结束停留在画板。日志显示关闭 Stage 前两个窗口 restore accepted=true。
- 原始结果：`.work/board119-regression-stage-return-failed.json` 保留此前候选的 3 次冷启动、预览通过及返回失败；`.work/board119-stage-final.json` 为最终包两种返回场景通过。失败尝试没有改写成成功。
- 系统手势退出、外部强制终止和窗口空间位置的目视复核未在本轮全部覆盖。当前结论针对已测操作链路，不宣称消除了所有 SDK 显示问题。

## 范围与交付

此修复移除了普通画板对失效 attachment 链路的依赖，没有宣称已确定 SDK 内部造成 GONE 的唯一原因。自动语义检查不代替空间位置、绘画触感和手腕输入的视觉验收。
