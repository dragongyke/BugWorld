# Stage 性能诊断 · 2026-10-19～20

状态：1.0.10 用户确认卡顿明显减轻，原生渲染 CPU 饱和现象解除；GPU 仍超出 90 Hz 预算。以下为诊断证据，不是帧率达标报告。

## 有效基线

- 用户进入花园并保持佩戴；场内 4 只昆虫（瓢虫、独角仙、两只蝴蝶）。
- 1.0.9 诊断包：天空深度写入开启，重复透明度 setter 已跳过，已加入交互回应与短暂提示；昆虫和场景资产未改变。
- PICO CLI `perf trace record`，默认预设，35 秒；`trace load` 检测到 Spatial 诊断数据，随后运行帧分析和 SQL 查询。
- 原始文件留在本地 `.work/stage110-active-baseline.perfetto-trace`，216,338,556 字节；不提交大体积原始系统 trace。分析查询保留在 `scripts/perf/`。

| 观测 | 结果 | 解释边界 |
| --- | --- | --- |
| 应用帧时长，319 帧 | 中位 109.239 ms，平均 106.647 ms，P95 208.261 ms | 不是合成器最终刷新率 |
| 空间 CPUTime 阶段 | 中位 201.308 ms，平均 214.764 ms | 阶段墙钟时间，可能含流水线等待；不可当纯 CPU 执行时间 |
| 空间 GPUTime 阶段 | 中位 16.764 ms，平均 17.746 ms | GPU 也超出 90 Hz 单帧预算，但不能解释全部百毫秒延迟 |
| 原生 `Eng-Render` 线程实际 CPU 调度 | 34.789 秒 / 约 35 秒 | 约占满一个 CPU 核，来自 `sched` 调度记录 |
| 应用主线程实际 CPU 调度 | 1.396 秒 / 约 35 秒 | 不支持“Kotlin 主循环计算占满 CPU”的判断 |
| 应用 `beginFrame` | 平均 102.871 ms | 大部分时间在等待原生帧推进 |
| 应用 `BugWorldStage:tick` | 平均 1.635 ms | 只是本地游戏逻辑，不包含原生渲染 |

结论：瓶颈重点转向原生渲染线程。尚不能从这些数据区分骨骼处理、实体/材质提交、透明度层级或其他原生操作，也不能仅据面数给出因果结论。

### 骨骼暂停的采样结果

基线 trace 实际跨度 34.996776 秒；暂停播放 trace 实际跨度 19.998423 秒，文件为 `.work/stage110-no-animation.perfetto-trace`（122,975,221 字节）。两者使用本地 PICO CLI 帧分析和同一条 `sched` SQL 查询；分析后两个会话均已关闭。结构化结果与 SQL 保存在 [Stage-Performance-Comparison.json](Stage-Performance-Comparison.json)。

| 观测 | 完整动画基线 | 暂停原生动画播放 |
| --- | --- | --- |
| 应用帧样本数 | 319 | 273 |
| 应用帧时长，中位 / P95 / 平均 | 109.239 / 208.261 / 106.647 ms | 30.159 / 131.036 / 68.700 ms |
| 空间 GPUTime，中位 / P95 / 平均 | 16.764 / 27.678 / 17.746 ms | 9.698 / 11.333 / 9.378 ms |
| 空间 CPUTime 阶段墙钟，中位 / 平均 | 201.308 / 214.764 ms | 144.933 / 145.032 ms |
| `Eng-Render` 实际 CPU 调度 | 34.788531 秒，单核 99.405% | 19.862716 秒，单核 99.321% |
| 应用主线程实际 CPU 调度 | 1.396238 秒，单核 3.990% | 0.892253 秒，单核 4.462% |
| `beginFrame` 平均墙钟 | 102.871 ms | 65.835 ms |
| `BugWorldStage:tick` 平均墙钟 | 1.635 ms | 1.395 ms |

暂停动画样本中仍有 136/273 个应用帧落在 100–200 ms 区间；用户也确认严重卡顿仍在。因此本次尝试不能作为修复交付。虽然这次记录的帧时长和 GPUTime 更低，原生 `Eng-Render` 仍几乎占满一个 CPU 核；`sched` 包括可能的忙等，不能把全部时间归因于骨骼计算。空间 CPUTime 是阶段墙钟而非纯 CPU 工作量，应用帧时长也不是合成器最终 FPS。

两次采样均为 4 只昆虫。基线数量见外部日志；暂停播放数量由采集会话的原始运行日志确认：设备时间 `20:22:36.203`、PID `32502`，`BugWorldStagePerf phase=first_visible_ready wall_ms=22571.428064 residents=4`，与暂停播放 trace 的应用 PID 一致。该条日志保留在采集会话输出中，trace 内的 `android_logs` 没有收录它。

比较边界：两次记录时长不同，头部朝向与热状态没有控制，且 trace 本身可能扰动性能。因此这里只报告实测差异，不给出严格的动画开销百分比或已定位根因的结论。

## 2026-10-20 · 1.0.10 无损合批与真机验证

用户确认画板已修复、Stage 仍卡顿。新日志重复显示昆虫出现后应用回调 P95 约 211 ms；这是应用回调间隔，仍不冒充合成器 FPS。

检查 GLB：每个物种的大部分网格共享父节点、蒙皮和材质，却各自形成独立图元。保留绘画绑定网格，合并同组其余网格，四模型图元从 449 降到 34；所有三角面、顶点属性、贴图、骨骼和动画数据不减量。源/派生文件重导入后的近景对照差不超过单个 8 位通道 1 级，数据与脚本见 [派生清单](../assets-src/insects-batched/manifest.json)。

透明度组件、材质克隆、骨骼播放、场景和高亮保持原策略，避免混改。用户进入花园并保持佩戴后录制 20 秒（实际 19.998823 秒），此时持久列表中 5 只昆虫，新作品的入场日志也已记录。用户随后明确确认“新昆虫出现，卡顿明显减轻”。

| 观测 | 1.0.10 合批后 |
| --- | --- |
| 应用帧时长，943 帧 | 中位 13.853 ms，平均 12.910 ms，P95 14.769 ms |
| 空间 CPUTime 阶段墙钟 | 中位 10.063 ms，平均 10.172 ms，P95 11.829 ms |
| 空间 GPUTime | 中位 17.736 ms，平均 17.442 ms，P95 19.392 ms |

采样证明本次原生渲染线程不再满核，百毫秒级应用帧长延迟显著减轻；与用户体感一致。但旧基线为 4 只、本次 5 只，视角和热状态未控制，不能给出严格因果提升百分比。图元数也不是实际 draw calls，应用帧数不能直接当作合成器 FPS。

GPU 平均约 17 ms，仍超出 90 Hz 的 11.11 ms 预算，工具记录 903 个空间帧中 887 个 Late。**不标记帧率达标或全部卡顿已解决**。0/1/10 只、长时间运行及一致视角的 GPU 细分测量留作下一步。
